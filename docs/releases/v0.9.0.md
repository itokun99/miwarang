# Miwarang Delegate v0.9.0

Unified, prompt-driven delegation. Miwarang is no longer an OMO route table:
it is a delegation tool any agent platform can call with a prompt, while each
backend harness owns its model and agent.

## Breaking changes

- **Routes removed.** `miwarang_delegate` now takes `prompt`, `mode`,
  `backend`, and `cwd` only. The `routes`, `defaultRoute`,
  `defaultModels`, `pricePolicy`, `defaultBackend`, and `blockNativeTask`
  config keys were removed; configs containing them fail validation with a
  migration message. Backend order and fallbacks live in the top-level
  `delegation` chain.
- **OpenCode runs through its CLI.** The experimental `opencode-v2` SDK
  backend was removed. OpenCode is now an `opencode-cli` command backend
  running `opencode run --agent {{agent}}` per the current
  [opencode.ai/docs](https://opencode.ai/docs/cli).
- **Miwarang never selects models.** All model plumbing (`{{model}}`
  placeholders, `listModelsArgv` probes, model candidate lists) was removed.
  Each harness owns its model.
- **Per-backend agents.** Each backend config may set `agent` (for example
  `Orchestrator` for OpenCode, `General` for Command Code); Miwarang passes
  it through `{{agent}}`. The delegate tool no longer accepts `target`,
  `model`, or `agent` parameters.
- The native-task interception hook was removed together with the route
  system; Miwarang is harness-agnostic, not OMO-specific.

## Preserved

- The OMO thread bridge: background runs keep `omoThreadId` alongside the
  backend `runId`, returned by `miwarang_wait` / `miwarang_cancel`.
- Provider-failure failover across the delegation chain (quota, rate limit,
  429, upstream session failures) for foreground calls and for background
  calls before a run ID exists.
- Run records under `runsDirectory` with the same lifecycle tools.
